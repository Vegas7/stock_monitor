# stockmon Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Build `stockmon`, a single low-memory Go program that monitors Misaka VPS plans and web pages for stock, auto-orders one Misaka plan as an unpaid invoice, and reports everything over Telegram. It's managed through a terminal menu on a Debian VPS.

**Package dependencies (no cycles):** `misaka` imports no other internal package. `check` imports `misaka` and `config`. `state` imports `check` and `misaka`. `monitor`, `order`, `service`, `menu`, and `lifecycle` sit on top.

**Architecture:** One static binary has these subcommands: `menu` (the default), `run` (the systemd service), `update`, `uninstall`, and `version`. The menu is the only writer of `config.json`, and the service is the only writer of `state.json`. Both files are written atomically. Each enabled item runs in its own goroutine and checks at a random 30–60 s interval. A pure policy function turns check results into status changes and Telegram messages. Misaka is reached through the web console's internal JSON API.

**Tech Stack:** Go 1.25, standard library, `github.com/PuerkitoBio/goquery` (CSS selectors), `golang.org/x/term` (hidden input), systemd, bash (`install.sh`), GitHub Actions (releases).

**Spec:** `docs/superpowers/specs/2026-11-21-stock-monitor-design.md` (read it alongside this plan).

## Global Constraints

- Module path is `github.com/Vegas7/stock_monitor` and the binary is named `stockmon`. Version is set by `-ldflags "-X main.version=vX.Y.Z"` and defaults to `dev`.
- **The repo is public.** Never commit real credentials, tokens, chat IDs, emails, `config.json`, or `state.json`. `.gitignore` covers `config.json`, `state.json`, `*.local.*`, and `/dist/`.
- Default paths: config `/etc/stockmon/config.json` (mode `0640`, directory `0750`, `root:stockmon`), state `/var/lib/stockmon/state.json` (mode `0600`, user `stockmon`), binary `/usr/local/bin/stockmon`, backup `/usr/local/bin/stockmon.prev`, unit `/etc/systemd/system/stockmon.service`.
- Check interval: uniform random in `[interval_min_sec, interval_max_sec]`, redrawn each check. The minimum allowed is 30, and max must be ≥ min. Defaults: 30 / 60.
- Setting defaults: `fail_warn_after` 3, `fail_remind_minutes` 60, `daily_heartbeat_hour` 9, `timezone` `Asia/Tokyo`.
- Web fetch: 20 s timeout, read at most 2 MB of the body, send a normal browser User-Agent.
- Misaka API base: `https://app.misaka.io/api/` (to be checked live, Task 13).
- Auto-order: `count: 1`, `issue_invoice: true`. Exactly one order per `arm_id`. **Never retry an order.**
- Login failure backoff: 5 min, then 15 min, then 60 min (60 min repeats), reset when the credentials change.
- Every error string passes through the redactor before it's logged or sent to Telegram.
- Telegram message prefixes, exactly: `stockmon started`, `🟢 IN STOCK: `, `⚪ Sold out again: `, `⚠️ Warning: `, `✅ Recovered: `, `🛒 Order placed: `, `🚨 Order problem: `, `💓 stockmon daily: `. Messages are plain text (no parse_mode) and truncated to 3500 characters.
- Release assets: `stockmon_linux_amd64`, `stockmon_linux_arm64`, `checksums.txt` (in `sha256sum` format).
- Memory target: under 20 MB RSS. The systemd unit sets `MemoryMax=64M` and `GOMEMLIMIT=24MiB`.

## Review Focus

1. **Telegram not set up yet when the service starts.** The service has to keep running and log to the journal instead of crashing or exiting. Test: Task 9, `TestRunWithoutTelegram`.
2. **Misaka returns an HTML page (maintenance or Cloudflare challenge) or JSON missing `available`.** This must be an error (format changed, warned immediately), never "out of stock". Test: Task 5, `TestPlansHTMLResponseIsFormatError` and `TestPlanMissingAvailable`.
3. **A web page built by JavaScript where an "out of stock" keyword is simply missing from the raw HTML.** That makes the item read "in stock" wrongly. When adding an item whose live test reads in stock, the menu must say so and ask for confirmation. Test: Task 10, `TestAddWebItemWarnsWhenInStockOnAdd`.
4. **Long error text** (a whole HTML error page inside an error message). Telegram rejects messages over 4096 characters. Messages are cut to 3500. Test: Task 3, `TestSendTruncates`.
5. **An item edited or removed in the menu while the service runs.** Its goroutine must stop, a changed item must restart with the new settings, and removed items must not warn. Test: Task 9, `TestReloadRemovesAndRestartsItems`.

### Task 5: Misaka API client

**Files:**
- Create: `internal/misaka/client.go` (transport, session, errors), `internal/misaka/api.go` (endpoints and types), `internal/misaka/url.go`
- Test: `internal/misaka/client_test.go`, `internal/misaka/api_test.go`, `internal/misaka/url_test.go`

**Interfaces:**
- Consumes: `misaka.Tokens`, `misaka.TokenStore`, `misaka.ErrFormatChanged` (Task 2, `internal/misaka/types.go`). Package `misaka` imports no other internal package.
- Produces:
  - `misaka.DefaultBaseURL = "https://app.misaka.io/api/"`
  - `misaka.ID`: holds the raw JSON value (`json.RawMessage`), with `MarshalJSON`/`UnmarshalJSON` passing the bytes through unchanged and `String()` for display. Region, plan, and image IDs are sent back exactly as received, because their type (number or string) hasn't been checked.
  - `misaka.New(baseURL string, username, password string, ts TokenStore, hc *http.Client) *Client`. The `Client` field `Now func() time.Time` is used for the backoff.
  - Requests go through `(*Client).do(ctx, method, path string, body, out any) error`. It sends the headers `Accept` and `Content-Type: application/json`, `X-Misaka-User-Agent: stockmon`, `X-Misaka-User-Time` (RFC 3339, UTC), `X-Misaka-User-TZ: Asia/Tokyo`, and `X-Misaka-User-Locale: en-US`. It also sends `Authorization: Bearer <Access or Sliding>`, except on paths starting with `session/`.
  - Session: with no token, log in first. A response with JSON `code == "token_not_valid"` triggers `POST session/refresh {refresh}`. That stores `access`, and a new `refresh` if one comes back. Then the request is retried once. If the refresh fails, log in and retry once.
  - `(*Client).Login(ctx) error`: `POST session/login {username, password}`. Success is a response with `user`. It stores `access_token`/`refresh_token`, or `sliding_token`. Failure returns an error wrapping `misaka.ErrLogin` with the `detail` text. After a failure, login is refused with an `ErrLoginBackoff` error (which wraps `ErrLogin`) until 5, 15, then 60 minutes have passed.
  - `misaka.APIError{Status int; Code, InternalCode, Detail string}`. `misaka.Unclear(err error) bool` is true for network errors, timeouts, 5xx, and bodies that can't be parsed.
  - A non-JSON success body (for example HTML) gives an error wrapping `misaka.ErrFormatChanged`.
  - Types:
    - `Region{ID ID; Slug, Name string; Available *bool; UnavailableReason string}`
    - `Plan{ID ID; Slug, Name string; Available *bool; UnavailableReason string; Prices map[string]float64}` (`Prices` is filled from the `price_<cycle>` keys)
    - `Image{ID ID; Slug, Name string}`
    - `SSHKey{ID ID; Name string}`
  - Endpoints:
    - `Regions(ctx) ([]Region, error)`: `GET mc2/regions`
    - `Plans(ctx, regionID ID) ([]Plan, error)`: `GET mc2/regions/{id}/plans`
    - `Images(ctx) ([]Image, error)`: `GET mc2/images?type=os&all=yes`
    - `SSHKeys(ctx) ([]SSHKey, error)`: `GET mc2/sshkeys/`, following pages via `next` if present, or accepting a plain array
    - `CalculatePrice(ctx, PriceRequest) (map[string]any, error)`: `POST mc2/instances/calculate_price/`
    - `CreateOrder(ctx, OrderRequest) (OrderResult, error)`: `POST mc2/instances/`
  - `PriceRequest{Plan ID; Count int; BillingCycle string; Coupon string `json:",omitempty"`}`
  - `OrderRequest{Region, Plan, Image ID; Count int; Keys []string; BillingCycle string; Config []OrderName; Coupon string (omitempty); IssueInvoice bool}`. JSON names: `region, plan, image, count, keys, billing_cycle, config, coupon, issue_invoice`. `OrderName{Name string}`.
  - `OrderResult{Orders []string; InvoiceID string}` (accepts numbers or strings in the JSON)
  - `misaka.ParseConsoleURL(u string) (region, plan, image string, err error)` handles `https://app.misaka.io/iaas/vm/create/{region}/{plan}/{image}`. The image part is optional.

### Task 7: Status and notification policy

**Files:**
- Create: `internal/monitor/policy.go`
- Test: `internal/monitor/policy_test.go`

**Interfaces:**
- Consumes: `state.ItemState`, `check.Result`, `check.Urgent`, `config.Item`, `config.Settings`, `redact.Redactor`.
- Produces: `monitor.Apply(prev state.ItemState, item config.Item, res check.Result, err error, now time.Time, s config.Settings, r *redact.Redactor) (next state.ItemState, msgs []string, becameInStock bool)`. It's a pure function. Messages use the exact prefixes from Global Constraints followed by the item `Name`, with the URL or console link on a second line. Rules:
  - Success when `prev.Warned`: `✅ Recovered: `. Reset `ConsecutiveFails` and `Warned`.
  - Success with `res.Status == InStock` and `prev.Stock != InStock` (including the first check, when it's `Unknown`): `🟢 IN STOCK: ` plus Detail. `becameInStock = true`.
  - Success with `OutOfStock` and `prev.Stock == InStock`: `⚪ Sold out again: `. Going from `Unknown` to `OutOfStock` sends nothing.
  - Error: `ConsecutiveFails++`, and `Stock` is left unchanged. Warn (`⚠️ Warning: <name>\n<redacted error>`) if not yet `Warned` and either `Urgent(err)` or `ConsecutiveFails >= FailWarnAfter`. If already `Warned` and `now - LastWarnAt >= FailRemindMinutes`, send a reminder with the same prefix plus `(still failing, N checks)`.
  - The console link for Misaka items is `https://app.misaka.io/iaas/vm/create/{region}/{plan}/{image}`.

### Task 9: Service (`stockmon run`)

**Files:**
- Create: `internal/service/service.go`, `internal/service/heartbeat.go`
- Modify: `cmd/stockmon/main.go` (add `run`, with `--config` and `--state` flags)

**Interfaces:**
- Consumes: everything above. `lifecycle.Latest` (Task 11) is optional and injected as a function so this task doesn't depend on Task 11.
- Produces: `service.Options{ConfigPath, StatePath, Version string; HTTP *http.Client; MisakaBaseURL, TelegramBaseURL string; Now func() time.Time; Rand func() float64; Sleep func(ctx, time.Duration) bool; Latest func(ctx) (string, error); Log *slog.Logger}` and `service.Run(ctx, Options) error`.
  - Start-up:
    1. Load the config. If it's invalid, log and wait for a valid one, re-checking every 5 s; don't exit.
    2. Open the state.
    3. Send `stockmon started vX: N items`, adding ` (after a restart)` when `!CleanShutdown`.
    4. Set `CleanShutdown=false`.
    5. Run `order.RecoverPending` and send its messages.
  - With no Telegram config, every notification goes to the log only (Review Focus 1).
  - One goroutine per enabled item. It waits a first offset of `Rand()*10s`, then loops: check, `monitor.Apply`, save the ItemState, send the messages. If `becameInStock && order.Armed`, it calls `order.Place` straight away and sends the result. Then it sleeps `min + Rand()*(max-min)` seconds.
  - Misaka items share one `misaka.Client`. It's rebuilt only when the credentials change, which resets the login backoff.
  - Reload: every 5 s, compare the config file's mtime. If it's valid, cancel the goroutines of removed or changed items (compare the item JSON) and start new or changed ones. If it's invalid, send `⚠️ Warning: config reload failed` once per mtime and keep the old config.
  - Heartbeat: when the local hour (config timezone) equals `DailyHeartbeatHour` and `LastHeartbeat` isn't today, send `💓 stockmon daily: ` plus one line per item (`name: in stock/out of stock/unknown[, failing N]`). If `Latest` reports a newer version than `Version` (checked at most once per 24 h), add `update available: vX → vY, run sudo stockmon update`.
  - On ctx cancel (SIGTERM/SIGINT in `main`), stop the goroutines, set `CleanShutdown=true`, and return nil.
